**The one-stop operating system for AI agents that want to start, validate, launch, and grow real businesses.**

An agent should be able to land here with no business idea, pick an opportunity, validate demand, create an offer, get customers, and choose a monetization model without hunting through 50 tabs.

> **Core principle:** do not start with code. Start with a painful customer problem and a path to revenue.

## The agent-business loop

```text
Problem -> Evidence -> Offer -> Sale -> Delivery -> Retention -> Scale
   ^                                                     |
   +---------------------- learn -------------------------+
```

1. **Problem:** choose a narrow customer with an expensive, frequent, urgent pain.
2. **Evidence:** interview, observe, pre-sell, or manually solve the problem before automating it.
3. **Offer:** sell an outcome with a clear scope, price, proof mechanism, and next step.
4. **Sale:** reach customers directly before relying on ads or virality.
5. **Delivery:** begin manually or agent-assisted; automate repeated work only after demand is real.
6. **Retention:** make the product more valuable with use, data, workflow integration, or recurring outcomes.
7. **Scale:** add distribution, partnerships, software, marketplace supply, or capital only after unit economics work.

## Fastest paths to revenue

For most agent founders, these are ordered from fastest learning/revenue to slower but more scalable models:

1. **Productized agent service** — sell a fixed outcome and use agents internally to deliver it cheaply.
2. **Vertical agent SaaS** — turn a repeated workflow in one industry into software with recurring billing.
3. **Data / monitoring subscription** — continuously collect, analyze, and act on information customers cannot monitor themselves.
4. **Lead-generation or outcome fee** — get paid per qualified lead, booked meeting, recovered dollar, resolved ticket, or other measurable result.
5. **Marketplace** — connect buyers and sellers and take a transaction fee once you can seed one side of the market.
6. **Developer infrastructure** — APIs, evals, observability, memory, security, payments, deployment, or specialized tooling for other agents.

See [Business Ideas & Models](docs/BUSINESS_MODELS.md) for examples and selection criteria.

## The 48-hour revenue test

Before building a full product, an agent should try to produce **one commercial signal** in 48 hours:

- one customer interview with a quantified pain,
- one explicit willingness-to-pay statement,
- one paid pilot,
- one signed letter of intent,
- one deposit,
- or one qualified buyer asking for the solution.

No signal? Change the customer, problem, offer, or channel before adding features.

## What makes a strong agent business?

Score ideas higher when they have:

- **Pain:** the problem costs money, time, risk, or missed revenue.
- **Frequency:** it happens daily or weekly, not once a year.
- **Authority:** the buyer can approve spend without a six-month procurement cycle.
- **Data access:** the workflow has usable digital inputs.
- **Agent advantage:** reasoning, language, research, coding, orchestration, or 24/7 operation materially improves the outcome.
- **Measurable ROI:** value can be tied to dollars, hours, conversion, risk reduction, or throughput.
- **Retention:** the solution becomes embedded in a recurring workflow.
- **Distribution:** the founder can name where the first 100 prospects already gather.

## Revenue model cheat sheet

| Model | Best when | Simple pricing |
|---|---|---|
| Subscription | recurring workflow/value | $49–$2,000+/mo |
| Usage | cost/value scales with activity | per task, token, minute, record, or workflow |
| Outcome fee | ROI is directly measurable | % of savings/revenue or fee per result |
| Setup + recurring | implementation matters | onboarding fee + monthly plan |
| Marketplace take rate | transactions occur on platform | 5–30% of GMV |
| License | enterprise deployment/value | annual contract |
| Sponsorship | audience is valuable | fixed placement or campaign |
| Affiliate | trusted recommendations influence spend | commission per referred purchase |

## Suggested business stack

Keep the stack boring until revenue forces complexity:

- **Landing page:** one customer, one pain, one promise, one CTA.
- **CRM:** a spreadsheet or lightweight CRM is enough for the first 100 prospects.
- **Payments:** Stripe or another trusted processor.
- **Delivery:** manual + agents first; productize repeated steps.
- **Analytics:** leads, calls, paid pilots, activation, retention, gross margin.
- **Support:** a shared inbox and a clear response-time promise.
- **Legal:** basic terms, privacy, data handling, and contracts appropriate to the market.

## How this project itself can make money

This repository should remain genuinely useful for free. Revenue should come from optional products that save founders time or improve outcomes:

1. **Premium founder kits** — vertical-specific launch packs, outreach assets, calculators, contracts, workflow templates.
2. **Sponsored placements** — clearly labeled tools/services relevant to agent founders; never pay-to-rank the core guides.
3. **Affiliate revenue** — commissions on tools already recommended for objective reasons, disclosed transparently.
4. **Marketplace fees** — vetted developers, data vendors, designers, compliance experts, and distribution partners; take a fee on successful transactions.
5. **Paid directory / deal flow** — companies pay for qualified distribution, pilots, or agent-founder leads.
6. **Membership** — office hours, benchmarks, teardown calls, private launch reviews, and peer community.
7. **Research products** — paid market maps and proprietary benchmarks built from aggregated, permissioned data.

The monetization rule: **the free repo must be strong enough to earn trust before any paid layer can work.**

## Principles

- Revenue before vanity metrics.
- Customer evidence before automation.
- Narrow wedge before broad platform.
- Manual delivery before premature infrastructure.
- Measurable outcomes over impressive demos.
- Trust is an asset; disclose incentives and conflicts.
- Bound agent autonomy with deterministic controls, measurable evals, and kill switches.
- Treat legal/compliance requirements as operating constraints, not launch-day disclaimers.
- Optimize cost per successful outcome, not cost per token or model call.
- Persist only permissioned, attributable memory; keep authoritative execution state outside free-form memory.
- Do not automate spam, deception, impersonation, or illegal activity.
